    5-3. 페이지와 구성도¶

    검증된 IaC가 생겼으니 이제 참석자가 읽을 모듈 페이지와 구성도를 만듭니다. 이 단계의 핵심은 Claude가 이미 저장소에 있는 파일(storyboard.md, AGENTS.md, static/cfn/, scripts/)을 근거로 쓰게 하는 것입니다. 페이지에 나오는 명령과 값이 템플릿과 어긋나지 않아야 합니다.

    1단계. 모듈 페이지 쓰기¶

    Claude Code에 입력:

    storyboard.md의 모듈 2 "TGW를 Cloud WAN에 연결"을 content/20-connect-tgw/index.ko.md로 써 줘.
AGENTS.md의 페이지 규칙을 따르고, 다음을 넣어 줘.

- 맨 앞: 이 모듈에서 바꾸는 것과 바꾸지 않는 것(VPC는 안 바꿈)
- 구성도: /static/images/arch-cloudwan-after.svg
- 비용 warning 알림 (core network edge, peering 시간당 요금, 요금 페이지 링크)
- 1단계: static/cfn/40-cwan-tgw-peering.yaml 배포. CloudFormation 탭과 AWS CLI 탭으로 같은 작업을 보여 줘
- 2단계: list-attachments로 세그먼트 매핑 확인 + SegmentName이 비었을 때 볼 것
- 3단계: 서울 prod RT에서 10.11.0.0/16이 아직 static인 이유(정적 경로 우선)
- 확인 체크리스트, 정리
명령은 템플릿의 파라미터 이름·스택 이름과 정확히 맞춰 줘. 예상 출력은 리허설 전이므로 주석을 남겨.

    Warning

    검증 체크포인트 — 페이지

    • 명령 ↔ 템플릿 대조. 페이지의 --parameter-overrides 이름이 40-cwan-tgw-peering.yaml의 Parameters와 같은가요? 스택 이름이 ws-ai-nssa-cwan- 접두어인가요? Claude에게 직접 시켜도 됩니다: "페이지에 나온 파라미터·스택 이름을 템플릿과 대조해서 다른 것만 표로 보여 줘."
    • --region. aws networkmanager는 us-west-2, aws ec2/aws cloudformation은 서울·도쿄가 맞나요?
    • 설명의 근거. "정적 경로가 전파 경로보다 우선"처럼 동작을 설명하는 문장에 출처가 있나요? 없다면 리허설 출력(5-4)으로 확인한 뒤 남깁니다.
    • 미리보기. Workshop Studio 문법(::alert, ::::tabs)이 깨지지 않는지 로컬 미리보기나 Workshop Studio 미리보기로 한 번 봅니다.
    예시 결과 보기

    ~/ws-solutions/cloudwan/sample-module/index.ko.md에 완성본이 있습니다. 구성은 다음과 같습니다.

    • 목표 3개 → 비용 warning → 변수 준비
    • 1단계 ::::tabs (CloudFormation / AWS CLI)
    • ::::expand "왜 VPC가 아니라 TGW 라우팅 테이블을 붙이나요?"
    • 2단계 list-attachments 표 출력, SegmentName이 비었을 때 info 알림
    • 3단계 prod RT 경로 표(10.11.0.0/16 static peering)
    • 확인 체크리스트 3개

    2단계. 구성도 만들기 (skill 사용)¶

    구성도는 그림 도구로 직접 그리지 않고 skill로 만듭니다. skill-aws-arch-diagram은 공식 AWS 아키텍처 아이콘으로 SVG·PNG·PPTX를 만드는 skill입니다. Claude는 레이아웃 명세(YAML)만 쓰고, 좌표 계산과 아이콘 배치는 skill의 스크립트가 합니다.

    skill 설치¶

    skill은 SKILL.md가 들어 있는 폴더입니다. 둘 중 한 곳에 두면 Claude Code가 자동으로 찾습니다.

    위치 범위
    ~/.claude/skills/<이름>/ 내 모든 프로젝트
    <프로젝트>/.claude/skills/<이름>/ 이 저장소만 (git으로 팀과 공유) 
    git clone https://github.com/conft2k/skill-aws-arch-diagram.git ~/.claude/skills/skill-aws-arch-diagram

    처음 그림을 그릴 때 skill이 공식 AWS 아키텍처 아이콘 패키지(약 14 MB)를 내려받습니다. 내보내기에는 uv가 필요합니다(Workshop IDE에 설치되어 있음).

    Claude Code를 다시 시작한 뒤 "사용할 수 있는 skill 목록을 보여 줘"라고 물어 skill-aws-arch-diagram이 보이는지 확인합니다.

    Before / After 그리기¶

    Claude Code에 입력:

    skill-aws-arch-diagram으로 구성도 두 장을 그려 줘. 원본 layout spec은 static/images/src/에, 결과 SVG와 PNG는 static/images/에.

1) arch-tgw-before: 서울(ap-northeast-2) Region에 TGW-SEL과 VPC prod-sel 10.1.0.0/16, dev-sel 10.2.0.0/16,
   도쿄(ap-northeast-1) Region에 TGW-TYO와 prod-tyo 10.11.0.0/16, dev-tyo 10.12.0.0/16.
   두 TGW 사이 TGW peering. 각 TGW에 prod RT, dev RT를 sub-caption으로.
2) arch-cloudwan-after: 같은 VPC·TGW에 더해 AWS Cloud 수준의 Cloud WAN core network(edge 2개, 세그먼트 prod·dev),
   각 TGW와 core network edge 사이 peering, route table attachment(prod RT→prod, dev RT→dev).
   TGW 간 peering은 없음.
skill의 예제 중 tgw-reference-architecture가 가장 가까울 거야. 레이아웃 검사(Layout OK)를 통과시켜 줘.

    Warning

    검증 체크포인트 — 구성도

    • 아이콘이 모두 공식 아이콘인가요? 글자만 있는 상자로 대신한 아이콘이 없어야 합니다.
    • CIDR·ASN·리전 이름이 템플릿과 같은가요? 그림은 검사 스크립트가 없으니 사람이 숫자를 대조합니다.
    • Before와 After를 나란히 놓았을 때 바뀐 것(Cloud WAN, attachment)과 바뀌지 않은 것(VPC, TGW)이 한눈에 보이나요?
    • 레이아웃 spec(YAML)도 커밋합니다. 다음에 그림을 고칠 때 Claude가 spec만 고치면 됩니다.

    3단계. 번역과 현지화 (소개)¶

    영문 워크숍이나 블로그를 바탕으로 한국어 워크숍을 만들 때가 많습니다. 이때는 skill-aws-ko-translation(AWS 한국어 문서 문체로 번역하고 코드·식별자·링크·Markdown 구조를 보존하는 skill)을 같은 방법으로 설치해 씁니다.

    git clone https://github.com/conft2k/skill-aws-ko-translation.git ~/.claude/skills/skill-aws-ko-translation

    Claude Code에 입력 (예):

    skill-aws-ko-translation으로 content/20-connect-tgw/index.en.md를 index.ko.md로 번역해 줘.
번역 뒤에 원문과 명령·코드 블록이 한 글자도 다르지 않은지 대조해 줘.

    참고: 스크린샷 자동화¶

    콘솔 화면이 필요한 페이지는 브라우저 자동화(예: Claude in Chrome)로 스크린샷을 찍고 필요한 영역만 잘라 넣을 수 있습니다. 이 워크숍에서는 다루지 않습니다. 콘솔 화면은 자주 바뀌므로, 가능하면 CLI 출력을 증적으로 쓰는 편이 유지보수에 유리합니다.

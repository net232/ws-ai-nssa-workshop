    1-1. 첫 세션¶

    목표¶

    • Claude Code가 Amazon Bedrock으로 연결되었는지 확인합니다.
    • 세션 안에서 파일 참조, 셸 실행, 중단, 되돌리기를 손에 익힙니다.
    • 권한 모드와 plan mode의 차이를 이해합니다.

    1. 설치와 Bedrock 연결 확인¶

    워크숍 IDE에는 Claude Code와 Bedrock 설정이 미리 들어 있습니다(/etc/profile.d). 자기 노트북을 쓰는 경우 같은 값을 셸 프로필에 넣습니다.

    claude --version
env | grep -E 'CLAUDE_CODE_USE_BEDROCK|AWS_REGION|LAB_REGION'
aws sts get-caller-identity

    기대 결과:

    CLAUDE_CODE_USE_BEDROCK=1
AWS_REGION=us-east-1
LAB_REGION=ap-northeast-2
    변수 의미
    CLAUDE_CODE_USE_BEDROCK=1 Anthropic API 대신 Amazon Bedrock으로 모델을 호출합니다. 자격 증명은 AWS SDK 기본 체인(인스턴스 역할, 프로필 등)을 씁니다.
    AWS_REGION=us-east-1 Bedrock을 호출할 리전입니다. Claude Code는 AWS_REGION → AWS_DEFAULT_REGION → 프로필의 region 순서로 리전을 정하므로, 여기서는 가장 먼저 적용되는 AWS_REGION으로 지정합니다.
    ANTHROPIC_MODEL (선택) 기본 모델을 바꿀 때 Bedrock 추론 프로파일 ID를 넣습니다. 세션 안에서는 /model로 고릅니다.
    LAB_REGION=ap-northeast-2 이 워크숍의 실습 리전입니다. Claude Code가 쓰는 변수가 아니라 워크숍 규칙용입니다.

    리전 함정: aws CLI에는 항상 --region ap-northeast-2

    Claude Code가 Bash 도구로 실행하는 aws 명령은 Claude Code 프로세스의 환경 변수를 그대로 물려받습니다. 즉 AWS_REGION=us-east-1이 aws CLI에도 적용되어, 리전을 빼면 VPC·NLB·스택이 us-east-1에 만들어집니다.

    그래서 이 워크숍에서는 aws CLI·CloudFormation 명령에 항상 --region ap-northeast-2를 붙인다는 규칙을 AGENTS.md에 적고(1-2), 리전 없는 aws 명령을 막는 hook을 둡니다(1-4).

    2. 첫 세션 시작¶

    mkdir -p ~/ws-lab && cd ~/ws-lab
claude

    처음 여는 폴더에서는 "이 폴더를 신뢰하는가"를 묻습니다. 실습 폴더이므로 신뢰합니다.

    Claude Code에 입력:

    지금 사용하는 모델과 AWS 자격 증명(계정 ID, 역할)을 알려 줘. aws CLI를 쓸 때는 --region ap-northeast-2를 붙여.

    Claude는 aws sts get-caller-identity 같은 명령을 실행하기 전에 승인을 요청합니다. 명령을 읽어 보고 허용합니다. 이것이 기본 권한 모드의 동작입니다.

    3. 기본 조작¶

    조작 방법 쓰는 때
    파일 참조 프롬프트에 @경로 (Tab으로 자동 완성) "이 템플릿 @infra/nlb.yaml 검토해 줘"
    셸 직접 실행 줄 맨 앞에 ! 예) ! aws ec2 describe-vpcs --region ap-northeast-2 결과를 Claude도 보게 하고 싶을 때
    작업 중단 Esc 방향이 틀렸을 때 바로 멈춤. 이어서 정정 지시
    되돌리기 입력창이 비어 있을 때 Esc 두 번, 또는 /rewind 대화와 Claude가 고친 파일을 이전 시점으로 되돌림
    여러 줄 입력 Shift+Enter (터미널에 따라 \ + Enter) 긴 지시, 표 붙여 넣기
    모드 전환 Shift+Tab 권한 모드 순환 (아래 5절)
    이전 세션 claude -c (이어서), claude -r (골라서) 다음 날 이어서 작업

    Warning

    /rewind는 Claude가 편집 도구로 바꾼 파일만 되돌립니다. Bash로 실행한 aws 명령이 만든 클라우드 리소스는 되돌리지 않습니다.

    4. 꼭 알아야 할 slash command¶

    명령 하는 일
    /help 명령 목록
    /init 현재 폴더를 분석해 CLAUDE.md 초안 생성 (1-2)
    /memory 적용 중인 메모리 파일(CLAUDE.md 등)을 열어 편집
    /model 모델 선택
    /permissions 허용·거부 규칙 확인과 편집 (1-3)
    /context 컨텍스트 창을 무엇이 얼마나 차지하는지 확인
    /compact [지시] 지금까지 대화를 요약해 컨텍스트를 비움. 예) /compact 테스트 결과 표는 유지
    /clear 대화를 비우고 새로 시작. 작업 주제가 바뀌면 사용
    /cost (/usage) 이 세션의 토큰 사용량과 비용
    /agents, /mcp, /hooks subagent, MCP 서버, hook 확인 (1-4)
    /doctor 설치·설정 진단

    5. 권한 모드와 plan mode¶

    Shift+Tab을 누를 때마다 default → acceptEdits → plan 순서로 모드가 바뀝니다. auto처럼 켜져 있는 모드가 있으면 이 순서에 함께 들어갑니다. 화면 아래에 현재 모드가 표시됩니다.

    모드 동작 이 워크숍에서
    기본 (default, 화면 표시 Manual) 파일 수정·명령 실행 전에 매번 묻습니다(허용 목록에 있는 것은 바로 실행) 처음 쓰는 작업, AWS에 변경을 가하는 작업
    acceptEdits 파일 편집은 묻지 않고, 명령 실행은 묻습니다 문서·템플릿을 많이 고칠 때
    plan 읽기와 조사만 하고 계획을 제안합니다. 승인해야 실행으로 넘어갑니다 모든 Lab의 첫 단계
    auto 분류기가 위험하다고 판단한 동작만 묻습니다 익숙해진 뒤, 실습 계정에서만

    bypassPermissions(--dangerously-skip-permissions)는 모든 확인을 건너뜁니다. AWS 자격 증명이 있는 환경에서는 쓰지 않습니다.

    미니 실습 (5분)¶

    1. Shift+Tab을 눌러 plan mode로 바꿉니다.
    2. Claude Code에 입력:
    ap-northeast-2의 기본 VPC 구성을 조사하고, 거기에 internet-facing NLB 하나를 띄우려면 무엇이 필요한지 계획만 세워 줘. 아무것도 만들지 마.
    1. Claude가 describe-* 명령으로 조사한 뒤 계획을 보여 줍니다. 승인하지 말고 거절한 다음, 다음 질문으로 계획을 검증해 봅니다.
    계획에서 네가 직접 확인한 사실과 추측한 것을 나눠서 표로 보여 줘.
    1. Shift+Tab을 눌러 화면 아래의 모드 표시가 plan mode에서 바뀌는 것을 확인하고 기본 모드로 돌아옵니다. Esc는 진행 중인 작업을 멈출 뿐 모드를 바꾸지 않습니다.

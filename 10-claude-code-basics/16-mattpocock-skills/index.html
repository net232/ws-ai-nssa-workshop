    1-6. Matt Pocock skills 활용¶

    직접 skill을 만들기 전에, 남이 잘 만든 skill을 써 보는 것이 가장 빠르게 배우는 방법입니다. Matt Pocock skills(mattpocock-skills plugin)는 "vibe coding이 아닌 실제 엔지니어링"을 목표로 만든 작은 skill 모음입니다. 각 skill은 조사, 계획 검증, 디버깅, 리뷰, 인수인계처럼 한 가지 일만 하고, 서로 조합해서 씁니다.

    • 저장소: github.com/mattpocock/skills (MIT 라이선스)
    • 이 워크숍 기준 버전: 1.3.1 (skill 27개)

    이 skill들은 원래 소프트웨어 개발용입니다. 그래도 조사 → 계획 → 구축 → 검증 → 디버깅 → 리뷰 → 인수인계 흐름은 Networking SA의 테스트·워크숍 작업과 같습니다. 이 페이지에서는 Lab에서 바로 쓸 수 있는 skill을 골라 소개합니다.

    1. 설치¶

    claude plugin marketplace add anthropics/claude-plugins-official
claude plugin install mattpocock-skills@claude-plugins-official

    Workshop IDE처럼 Amazon Bedrock으로 쓰는 Claude Code에는 공식 marketplace(claude-plugins-official)가 자동으로 등록되지 않을 수 있습니다. 그때 바로 install하면 Plugin "mattpocock-skills" not found in marketplace "claude-plugins-official" 오류가 납니다. 그래서 첫 줄로 marketplace를 먼저 등록합니다. 이미 등록되어 있다면 첫 줄은 건너뛰어도 됩니다.

    plugin으로 설치하면 skill이 자동으로 업데이트됩니다. skill 파일을 직접 고쳐 쓰고 싶다면 skills.sh로 프로젝트에 복사하는 방법도 있습니다. 다만 두 방법을 함께 쓰면 같은 skill이 두 번 등록되므로 하나만 고릅니다.

    설치를 확인합니다. Claude Code를 다시 시작한 뒤 입력창에 /grill까지 입력하면 자동완성 목록에 grill-me, grilling, grill-with-docs가 보입니다.

    Info

    plugin skill의 정식 이름은 plugin이름:skill이름입니다(예: /mattpocock-skills:grill-me). Claude Code에 같은 이름의 기본 명령이 있을 때는 정식 이름을 씁니다. 예를 들어 /code-review가 그렇습니다.

    2. 두 종류의 skill: 직접 부르는 것과 Claude가 알아서 쓰는 것¶

    종류 frontmatter 호출 방법 예
    사용자 호출 전용 disable-model-invocation: true 사용자가 /이름으로만 실행 /grill-me, /handoff, /retro, /teach, /to-questionnaire, /wait-what, /ask-matt
    모델 호출 가능 (없음) /이름으로 실행하거나, 요청이 description과 맞으면 Claude가 스스로 불러 씀 research, diagnosing-bugs, grilling, wizard, prototype, tdd, writing-for-agents

    예를 들어 "이 NLB 연결 문제 디버깅해 줘"라고만 입력해도 Claude가 diagnosing-bugs를 불러올 수 있습니다. 이렇게 Claude가 스스로 불러오는 skill은 description이 언제 쓸지를 알려 주는 트리거 역할을 합니다. Lab 6에서 net-feature-test skill에 disable-model-invocation: true를 넣는 것도 같은 원리입니다. 배포까지 이어지는 절차는 사람이 직접 시작할 때만 실행되게 하려는 것입니다.

    3. Networking SA를 위한 추천 skill¶

    아래 표는 skill이 무엇을 하는지 정리한 참고표입니다. 각 skill이 라이프사이클 단계에 그대로 맞는지, 원칙만 가져와야 하는지는 2. 라이프사이클 개요의 "Matt Pocock skills와 연결"에서 다룹니다.

    라이프사이클 skill 하는 일 이 워크숍에서 쓰는 곳
    1 Discover /research 백그라운드 agent가 공식 문서 같은 1차 출처로 질문을 조사하고, 주장마다 출처를 붙인 Markdown 파일을 저장합니다. 조사하는 동안 다른 일을 계속할 수 있습니다. Lab 1: NLB mTLS 문서 조사
    2 Plan /grill-me 계획을 집요하게 인터뷰합니다. 결정 사항을 트리로 펼치고, 지금 답할 수 있는 질문을 한 번에 묻고, 질문마다 추천 답을 함께 냅니다. 환경에서 찾을 수 있는 사실은 사용자에게 묻지 않고 직접 찾습니다. Lab 1: 테스트 계획 검증, Lab 5: 워크숍 스토리보드 검증
    2 Plan /grill-with-docs /grill-me와 같지만, 정해진 용어와 결정을 GLOSSARY.md와 ADR(docs/adr/)에 기록합니다. 저장소에서 오래 이어지는 작업에 씁니다. Lab 5: 워크숍 저장소
    2 Plan /to-questionnaire 혼자 정할 수 없는 결정을 다른 사람이 채울 질문지로 만듭니다. 서비스팀이나 고객에게 확인할 항목 정리
    3 Build /prototype 설계 질문 하나에 답하기 위한 버릴 시안을 만듭니다. 로직이나 상태 모델을 눌러 볼 수 있는 HTML 한 장, 또는 UI 시안 여러 개입니다. 예: Cloud WAN 세그먼트와 attachment 규칙을 눌러 보는 HTML로 정책 설계를 먼저 확인
    3 Build wizard 사람만 할 수 있는 단계를 하나씩 안내하는 대화형 bash 스크립트를 만듭니다. 원문이 드는 쓰임새는 인프라 프로비저닝, 자격 증명 설정, 처음 보는 콘솔 따라가기, 일회성 마이그레이션이나 전환(cutover)입니다. agent가 직접 할 수 있는 단계에는 쓰지 않습니다. 네트워크에서는 Direct Connect LOA 처리, 다른 계정에서 RAM 공유 수락, 온프레미스 라우터 설정, TGW → Cloud WAN 전환(Lab 5-4), Workshop Studio 이벤트 준비
    3 Build /implement 스펙이나 티켓을 받아 tdd로 구현하고 code-review로 리뷰한 뒤 커밋합니다. 타입 검사와 테스트 스위트를 전제로 합니다. IaC 작성에는 원칙만 가져옵니다: test-plan.md를 스펙으로, cfn-lint·local-rehearsal.sh를 테스트로
    5 Troubleshoot diagnosing-bugs 가설부터 세우지 않습니다. "이 버그에서 실패하는 명령 하나", 즉 피드백 루프부터 만들고 그다음에 원인을 좁힙니다. 출력에 들어 있는 비밀 값은 가립니다. Lab 4: 장애 진단
    6 Document writing-for-agents AGENTS.md, CLAUDE.md, SKILL.md처럼 agent가 읽을 문서를 쓰는 원칙입니다. Module 1.2, Lab 6: skill 작성
    (학습) /teach 지금 작업 폴더를 학습 공간으로 삼아, 여러 세션에 걸쳐 개념을 가르칩니다. 수업은 HTML로 만들어집니다. 새 서비스 개념을 미리 공부할 때
    7 Review /mattpocock-skills:code-review 기준점(commit, branch) 이후 변경을 두 축으로 리뷰합니다. 저장소 규칙을 지켰는지(Standards)와 원래 요구 사항을 만족하는지(Spec)를 subagent 두 개가 병렬로 검토합니다. Lab 6: 리뷰
    8 Package /handoff 지금 대화를 다음 세션이나 다른 agent가 이어받을 인수인계 문서로 압축합니다. 긴 작업을 /clear 전에 넘길 때
    8 Package /retro 세션을 돌아보고 코드가 아니라 작업 환경을 어떻게 고칠지 제안합니다. 대상은 AGENTS.md 규칙, 자동 검사, skill입니다. Lab 6 마무리

    모를 때 쓰는 skill도 있습니다.

    • /ask-matt: 지금 상황에 어떤 skill이나 흐름이 맞는지 알려 주는 안내 skill입니다.
    • /wait-what: 방금 받은 설명이 이해되지 않을 때, 다른 방식으로 다시 설명하게 합니다.

    4. 미니 실습 (10분)¶

    4-1. /grill-me로 테스트 아이디어 검증하기¶

    Claude Code에 입력:

    /grill-me 신규 출시된 NLB mutual TLS를 고객 데모용으로 테스트하려고 해. internal NLB 하나에 클라이언트 인증서를 여러 종류로 바꿔 가며 허용/거부를 확인할 생각이야.

    Claude가 번호 붙은 질문과 추천 답을 함께 냅니다. 예를 들면 "trust store에 CRL도 넣을 것인가", "passthrough 모드도 비교할 것인가", "인증서는 어디서 발급할 것인가" 같은 질문입니다. 추천 답이 맞으면 yes로 받고, 아니면 고쳐서 답합니다. 두세 라운드 진행해 본 뒤 Esc로 멈춥니다. 본격적인 계획은 Lab 1에서 세웁니다.

    확인할 점

    • 질문이 결정(무엇을 할지)에 관한 것이고, 찾아보면 알 수 있는 사실(예: "NLB가 mTLS를 지원하나요?")은 묻지 않는가?
    • 내 답에 따라 다음 라운드 질문이 달라지는가?

    4-2. /research를 백그라운드로 돌리기¶

    Claude Code에 입력:

    /research NLB mutual TLS의 trust store 제약 사항(CA 번들 크기, 인증서 체인 깊이, CRL 개수, 지원 키 알고리즘)을 AWS 공식 문서 기준으로 조사해서 notes/nlb-mtls-limits.md로 저장해 줘.

    조사는 백그라운드 agent가 진행합니다. 그동안 다음 페이지를 읽거나 다른 질문을 할 수 있습니다. 완료 알림이 오면 파일을 열어 각 주장에 출처 URL이 붙어 있는지 확인하고, 링크 두세 개를 직접 열어 봅니다.

    5. 저장소에서 본격적으로 쓰기: /setup-matt-pocock-skills¶

    engineering 계열 skill(to-spec, to-tickets, triage, code-review 등)은 저장소마다 다음 정보를 알아야 합니다.

    • 이슈 트래커: GitHub, GitLab, 또는 로컬 Markdown(.scratch/)
    • triage 라벨
    • 도메인 문서 위치: GLOSSARY.md, docs/adr/

    저장소에서 처음 쓸 때 /setup-matt-pocock-skills를 한 번 실행합니다. 이 skill은 저장소를 먼저 살펴보고 추천값을 보여 준 뒤, 사용자가 확인하면 docs/agents/ 아래에 설정 문서를 씁니다. 그리고 CLAUDE.md가 있으면 그 파일에, 없으면 AGENTS.md에 ## Agent skills 섹션을 추가합니다. 이 워크숍의 starter kit처럼 CLAUDE.md가 @AGENTS.md만 불러오는 구조라면, 규칙이 한곳에 모이도록 AGENTS.md에 넣어 달라고 직접 말해 줍니다.

    예: 이 워크숍 저장소에 적용한 결과 

    ## Agent skills

### Issue tracker
Issues live in GitHub Issues, managed with the `gh` CLI. See `docs/agents/issue-tracker.md`.

### Triage labels
Uses the five default triage labels: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`.

### Domain docs
Single-context: one `GLOSSARY.md` and `docs/adr/` at the repo root. See `docs/agents/domain.md`.
    GLOSSARY.md에 "trust store", "identity filter", "segment"처럼 팀이 쓰는 용어를 정해 두면, 이후 /grill-with-docs, diagnosing-bugs, code-review가 같은 용어로 일합니다.

    Info

    테스트 한 번으로 끝나는 작은 폴더(예: ~/ws-lab)라면 setup 없이 /grill-me, /research, diagnosing-bugs, /handoff만 써도 충분합니다. 워크숍 저장소처럼 오래 관리하는 곳에서 setup을 하세요.

    6. 쓸 때 주의할 점¶

    • skill도 프롬프트입니다. 처음 쓰는 skill은 SKILL.md를 먼저 읽어 보세요. 무엇을 하고, 무엇을 쓰고, 어디서 승인을 받는지 알 수 있습니다. plugin 파일은 ~/.claude/plugins/ 아래에 있습니다.
    • 개발용 가정을 걸러 씁니다. tdd, to-tickets, implement는 애플리케이션 코드와 테스트 프레임워크를 전제로 합니다. 네트워크 테스트에서는 "테스트 케이스를 먼저 정하고, 실패하는 것을 확인한 뒤 고친다"는 원칙만 가져와도 충분합니다.
    • 인터뷰는 토큰을 씁니다. /grill-me는 라운드가 여러 번 이어질 수 있습니다. 결정할 것이 다 정해졌으면 바로 멈춰도 됩니다.
    • 내 skill의 본보기로 씁니다. 짧은 description, 언제 쓰는지 알려 주는 트리거 문구, 단계마다 "완료 조건"을 두는 방식은 Lab 6에서 net-feature-test를 만들 때 그대로 따라 할 만합니다.

    1-2. CLAUDE.md와 AGENTS.md¶

    목표¶

    • Claude Code가 어떤 메모리 파일을 언제 읽는지 이해합니다.
    • CLAUDE.md와 AGENTS.md를 나눠 쓰는 이유를 이해합니다.
    • starter kit을 실습 폴더에 적용하고 자기 환경에 맞게 고칩니다.

    1. 메모리 파일의 계층¶

    Claude Code는 세션을 시작할 때 아래 파일을 찾아 시스템 지시에 넣습니다. 위쪽이 넓은 범위, 아래쪽이 좁은 범위입니다.

    범위 위치 공유 넣을 내용
    조직 관리자가 배포하는 정책 위치 조직 전체 보안 정책 (참석자는 신경 쓰지 않아도 됨)
    개인 ~/.claude/CLAUDE.md 나만 (모든 프로젝트) 응답 언어, 개인 작업 습관. 예) "설명은 한국어로"
    프로젝트 ./CLAUDE.md 또는 ./.claude/CLAUDE.md git으로 팀 공유 리전·태그·검증 규칙, 폴더 구조
    하위 폴더 ./infra/CLAUDE.md 등 git으로 팀 공유 그 폴더 파일을 다룰 때만 필요한 규칙. 해당 폴더를 읽을 때 불러옴
    자동 메모리 ~/.claude/projects/<프로젝트>/memory/ 나만 Claude가 작업하며 배운 것을 스스로 기록. /memory로 확인·삭제
    • @경로 import: CLAUDE.md 안에 @AGENTS.md, @docs/conventions.md처럼 쓰면 그 파일 내용을 함께 불러옵니다.
    • /init: 현재 폴더를 분석해 CLAUDE.md 초안을 만듭니다. 기존 저장소에 처음 들어갈 때 유용하지만, 결과는 반드시 직접 다듬습니다.
    • /memory: 지금 적용 중인 메모리 파일 목록을 보고 편집기로 엽니다.

    2. AGENTS.md와의 관계¶

    AGENTS.md는 여러 코딩 에이전트(Codex CLI 등)가 공통으로 읽는 프로젝트 지시 파일입니다. Claude Code는 CLAUDE.md를 읽으므로, 다음처럼 내용은 AGENTS.md에 쓰고 CLAUDE.md는 한 줄로 가져옵니다.

    @AGENTS.md

    이렇게 하면 Lab 6에서 Codex로 교차 리뷰할 때도 같은 규칙이 적용됩니다. Claude Code에만 해당하는 내용(예: skill 이름)만 CLAUDE.md에 덧붙입니다.

    3. 좋은 CLAUDE.md / AGENTS.md 쓰기¶

    원칙 나쁜 예 좋은 예
    확인할 수 있게 "조심해서 작업해" "delete-* 실행 전에 대상 목록을 보여 주고 확인받는다"
    이유를 함께 "리전을 붙여라" "aws CLI에 --region ap-northeast-2를 붙인다. AWS_REGION은 Bedrock용 us-east-1이 상속되기 때문"
    짧게 서비스 설명 수십 줄 규칙과 경로만. 긴 지식은 skill이나 docs/로 빼고 링크
    모델이 모르는 것만 "VPC는 가상 네트워크다" "이 계정은 10.0.0.0/8을 온프레미스가 쓰므로 VPC는 172.16.0.0/12에서 할당"
    금지와 대안을 같이 "프로덕션 금지" "프로필 prod*는 쓰지 않는다. 실습은 --profile lab"
    출처 요구 — "신규 기능 동작은 AWS 문서로 확인한 것만 쓰고 URL을 남긴다"

    Info

    메모리 파일은 매 세션 컨텍스트를 차지합니다. 200줄을 넘기 시작하면 skill(필요할 때만 로드)이나 하위 폴더 CLAUDE.md로 나눕니다.

    4. Networking SA용 예시¶

    starter kit의 AGENTS.md(요약):

    # <프로젝트 이름> — 신규 기능 테스트 / 워크숍 저장소

## 환경
- 실습 리전: ap-northeast-2. aws CLI·CloudFormation 명령에는 항상 --region ap-northeast-2를 붙인다.
  - 이유: Claude Code가 Bedrock용 AWS_REGION=us-east-1을 쓰고, 이 값이 aws CLI에도 상속된다.
- 모든 리소스에 태그 Project=ws-ai-nssa, Owner=<이름>. 스택 이름 접두어 ws-ai-nssa-.

## 작업 규칙
- 신규 기능의 동작·파라미터·CFN 속성은 AWS 문서로 확인한 것만 쓴다. 못 하면 TODO(확인 필요).
- 큰 작업은 plan mode로 계획을 먼저 보여 준다.
- 삭제 명령 전에는 대상 목록을 보여 주고 확인받는다.

## 검증
- cfn-lint 통과 후 배포. 테스트 결과는 기대값/실제값/명령 출력을 results.md에 남긴다.

cd ~/ws-lab && git init -q && ls -la . .claude
    1. Claude Code를 다시 시작하고(/exit 후 claude) 입력:
    지금 적용된 프로젝트 규칙을 다섯 줄로 요약해 줘. 그리고 AGENTS.md의 <...> 자리표시자를 찾아서 나에게 값을 물어본 뒤 채워 줘.

    2. 개인 메모리에 응답 언어 규칙을 넣습니다.
    mkdir -p ~/.claude && printf '# 개인 지침\n- 설명은 한국어로. 코드·명령·에러 원문은 그대로 둔다.\n' >> ~/.claude/CLAUDE.md

    정리¶

    라이프사이클의 마지막 단계는 정리입니다. 테스트가 끝난 리소스를 남겨 두면 비용이 계속 나가고, 다음 테스트에 영향을 줍니다. 삭제도 Claude에게 맡길 수 있지만, 무엇을 지울지는 사람이 확인합니다.

    1. Claude에게 삭제 계획 받기¶

    cd ~/ws-lab
claude

    Claude Code에 입력:

    이 워크숍에서 만든 리소스를 정리하려고 해. 먼저 plan mode로 다음을 보여 줘. 아직 아무것도 지우지 마.
1. --region "$LAB_REGION" 과 ap-northeast-1 에서 이름이 ws-ai-nssa 로 시작하는 CloudFormation 스택 목록과 상태
2. 스택 밖에서 만든 리소스(S3 객체, ACM 인증서, Cloud WAN 리소스)가 있는지
3. 삭제 순서와 명령 (의존 관계 때문에 순서가 중요한 것 표시)

    확인할 점

    • 계획에 Workshop IDE 스택(ws-ai-nssa-ide)이 들어 있으면 마지막으로 미룹니다. 지금 실행 중인 터미널이 그 인스턴스 위에 있습니다.
    • S3 버킷은 객체를 먼저 비워야 스택 삭제가 성공합니다.
    • Starter kit의 hook(guard-aws.sh)은 Claude가 직접 실행하는 aws 삭제 명령에만 확인을 요청합니다. bash cleanup.sh처럼 스크립트 안에서 실행되는 명령은 hook이 보지 못하므로, 스크립트를 실행하기 전에 내용을 읽고 대상 계정을 확인합니다. 정리 스크립트도 시작할 때 계정과 리전을 보여 주고 확인을 받습니다.

    2. 삭제 실행¶

    계획을 확인한 뒤 승인합니다. 참고 답안의 삭제 스크립트를 직접 실행할 수도 있습니다.

    bash ~/ws-solutions/nlb-mtls/scripts/cleanup.sh

    Cloud WAN을 배포했다면 bash ~/ws-solutions/cloudwan/scripts/cleanup.sh를 실행합니다. 이 스크립트는 ws-ai-nssa-cwan-attach-*(core network peering과 route table attachment) → core → routes-* → peering → base-* 순서로 스택을 지웁니다. core network와 attachment는 삭제하는 데 시간이 걸립니다.

    3. 남은 리소스 확인¶

    for r in ap-northeast-2 ap-northeast-1; do
  echo "== $r"
  aws resourcegroupstaggingapi get-resources --region "$r" \
    --tag-filters Key=Project,Values=ws-ai-nssa \
    --query 'ResourceTagMappingList[].ResourceARN' --output text
done

    ws-ai-nssa-ide 스택의 리소스만 남았다면 정리가 끝난 것입니다.

    4. Workshop IDE 삭제 (내 계정에서 진행한 경우)¶

    작업 폴더에서 남겨 둘 파일(research.md, test-plan.md, 직접 만든 skill 등)을 먼저 내려받거나 git 저장소에 push합니다. 그다음 CloudFormation 콘솔에서 ws-ai-nssa-ide 스택을 삭제합니다. AWS 이벤트 계정이라면 이벤트가 끝날 때 계정이 회수되므로 따로 삭제하지 않아도 됩니다.
